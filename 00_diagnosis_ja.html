00 ・ 授業時間と失点の原因

現状診断と改善戦略

成績が伸びない原因を、授業時間と Examiner Report の2つの根拠から特定し、優先順位の高い打ち手を決める。

⏱ 1. 授業時間 vs Cambridge 想定学習時間

Cambridge は IGCSE で約130時間、AS で約180時間、A Level 全体で約360時間の guided learning hours(GLH)を想定している(シラバス Guided learning hours)。

コース学年週あたり年間授業時間*Cambridge想定差
IGCSE 0478G9 + G1080分×2 + 40分 = 200分約107h × 2年 = 約213h約130h+約83h(余裕)
AS 9618G1180分×3 = 240分約128h約180h−約52h(充足率71%)
A Level 後半G12(5月の試験まで約26週)80分×3 = 240分約104h約180h−約76h(充足率58%)
AS + A2 合計G11–G12約232h約360h−約128h(充足率64%)

* 年間32授業週で計算(休み・試験・行事を除いた仮定)。実際の週数に合わせて差し替えること。想定時間の出典:Cambridge 0478 / 9618 シラバス「Guided learning hours」。

示唆: IGCSE は時間に余裕があり、ここは「成績が悪い」原因を時間に求められない。 一方、AS・A2 は構造的に時間が足りない。授業の進め方を変えない限り、同じ指導で成績は上がらない。
設計の基本方針: (1) IGCSE:余った約80時間を過去問演習・プログラミング・command word の訓練に使う。 (2) AS・A2:授業はつまずきの解消とフィードバックに集中し、初回の説明は事前学習(NotebookLM教材・Study Guide・動画)に移す。

🔍 2. 失点の4つの原因(Examiner Report より)

Cambridge の Principal Examiner が毎年繰り返し指摘しているパターンを4つに分類した。

原因① 問われたことに答えていない(読解・context・command word)

  • generic な答え:シナリオが与えられているのに一般論で答える。「machine learning が検索エンジンでどう使われるか」の問いに、一般的な ML の説明だけを書く。 0478 ER Mar 2025 P12 / 0478 ER Jun 2026 P11–13
  • command word の不一致:explain に対して describe 止まり。explain は「どのように」まで必要。 0478 ER Jun 2025 P22 / Jun 2026 P22–23 / 9618 ER Jun 2025 P31–33
  • 除外された答えを書く:「memory management 以外の OS タスクを2つ」で memory management を書く。例示された名前(password)の言い換え(PIN)は不可。 9618 ER Jun 2025 P11–13
  • 同じ内容を言い換えて2点取ろうとする:表現が違っても意味が同じなら1点。 9618 ER Jun 2025 P11–13, Nov 2025 P11–13
  • 問いの中身を取り違える:input device を問われて output device を答える。目的/特徴/利点の違いを区別しない。 0478 ER Mar 2024 P12 / Mar 2025 P12 / Mar 2026 P12

原因② 専門用語と正確さの不足(technical language)

  • 0478 Paper 1 は 2024年6月から2026年6月まで、ほぼ毎回「technical terminology をもっと使うこと」が Key message の筆頭。 0478 ER Jun 2024 / Nov 2024 / Jun 2025 / Jun 2026 P11–13
  • プロセスの説明が不正確:例)fetch-decode-execute で、メモリ上の「アドレス」と「命令そのもの」を混同し、MDR を最初のレジスタとする。 0478 ER Jun 2026 P11 Q2
  • 「computer が instructions を execute する」ではなく「understand する」と書く等、技術的に不正確な表現。 0478 ER Mar 2026 P12
  • 繰り返される誤概念:16進数は少ないメモリで保存できる/2進数で表せる最小の整数は1/actuator がモニターの表示を変える/1 KiB = 1000 bytes。 0478 ER Mar 2024 P12, Mar 2025 P12, Jun 2026 P11 Q1(b)
  • 9618 P3:packet switching と circuit switching の混同、interpreter の説明に compile の内容を書く、浮動小数点の exponent ミス。 9618 ER Jun 2025 P31 Q2(a), Q3(b), Q6

原因③ pseudocode・プログラミングの細部のミス(最も点を落とす)

  • CIE pseudocode の構文を知らない:IF の ENDIF 欠落/WHILE の ENDWHILE 欠落/procedure の END 欠落。 9618 ER Jun 2025 P22 Q7, Q5(b)
  • file handling の誤り:OPENFILE の mode 違い、CLOSEFILE や EOF() にファイル名がない。 9618 ER Jun 2025 P22 Q5(b) / P23
  • 予約語を変数名に使う(String、LENGTH、MONTH、TODAY)。2D array の添字の書き方の誤り。 9618 ER Jun 2025 P22 / P23
  • 設計を飛ばしてすぐコードを書く:count-controlled か conditional loop か、IF の連続か CASE か、関数の引数は何か、を決めていない。 9618 ER Jun 2025 P23 Key messages
  • 「State a value」に変数名を書く(BonusPay など)。テストデータの条件(rubric)を読まない。 9618 ER Jun 2025 P21 Q2(b)(i), Q6(a)
  • 0478 P2:short-answer に Python を書く(許されるのは15点のシナリオ問題だけ)/syllabus の pseudocode と違う形で書く/flowchart の記号の誤用/trace table が弱い。 0478 ER Jun 2024 P21, Jun 2026 P21–23
  • 0478 15点シナリオ:scenario を最後まで読まずに書き始める、与えられた変数・配列を使わない(宣言不要と書いてあるのに宣言する)、コメントが少ない。 0478 ER Mar 2024, Jun 2025, Jun 2026 P22
  • 9618 P4:evidence document の体裁(白地に黒字、色付き文字なし、indentation 維持、全 input/output が見えるスクリーンショット、header に centre/candidate number)。 9618 ER Jun 2025 P41–43

原因④ 時間不足(AS・A2)

上の表のとおり、AS は約52h、A2 は約76h、授業時間が想定を下回る。さらに A2 は P4(2h30の実技)の練習時間が授業内に確保されにくい。

  • 授業内で「初回説明」をすると、演習・フィードバックの時間が消える。
  • 過去問演習が試験直前に集中し、弱点が分かってから直す時間がない。

🎯 3. 原因ごとの打ち手(優先度順)

#打ち手効く原因主に取り戻す試験詳細
1全授業の最後5分に「1問ミニ試験」(command word と context を必ず指定)①②0478 P1/P2, 9618 P1/P305・06

📈 4. 追跡する指標(学期ごと)

「成績が上がったか」を学期末に判断できるよう、点数だけでなく失点の種類を記録する。

  • コンポーネント別の得点率(0478: P1/P2、9618: P1/P2/P3/P4)を mock ごとに記録し、前回との差を見る。
  • 失点の分類:各失点を ①読解/context/command word ②用語・誤概念 ③構文/プログラミング ④未習 のどれかに分類する(上の4原因と同じ)。
  • pseudocode 構文ミス数(ENDIF/ENDWHILE/CLOSEFILE/予約語)を1答案あたりで数える。目標は継続的に減ること。
  • P4:evidence document の体裁チェック(全項目クリアの提出割合)。
実データの差し込み欄: 直近の mock / MYE / 本試験のコンポーネント別得点が分かれば、 ここに学年別の表を追加し、上の4原因のうちどれが最も点を失っているかを特定します。現時点では Examiner Report の一般傾向に基づく診断です。

🧾 5. 理事会への説明ポイント

  • 授業時間:AS・A2 は Cambridge 想定の64%(約232h / 約360h)。構造的な不足があり、授業設計の変更で補う。
  • 失点の原因は特定可能:Examiner Report が毎年同じ4点を指摘しており、いずれも指導で改善できる。
  • 改善策は計測できる:コンポーネント別得点と失点分類を学期ごとに記録し、前学期と比較する。
  • IGCSE は時間的余裕がある:約83hの余剰を試験演習に配分し、P2 の15点シナリオを重点強化する。
