試験技術(Command word・解答フレーム・構文)

command word の定義、問題タイプ別の解答フレーム、pseudocode 構文チェックリスト、mark scheme の読み方。

🔑 1. Command word(Cambridge の定義)

定義は 0478・9618 シラバス「Command words」から。explain は describe より多く書くことを Examiner が毎回指摘している。

Command wordCambridge の定義書き方(教員向けの指導)
State / Give / IdentifyState: express in clear terms / Give: produce an answer from a given source or recall / Identify: name/select/recognise短く正確に。説明は不要。点数 = 書くポイントの数。
Definegive precise meaning用語の正確な定義。例だけでは不可。
Describestate the points of a topic / give characteristics and main features特徴・主な点を挙げる。「何であるか」。
Explainset out purposes or reasons / make the relationships between things clear / say why and/or how and support with relevant evidence「なぜ/どのように」まで。1点の主張 + 理由(展開)の形。Examiner Report の趣旨:explain は「どのように」、describe は「何を」。
Outlineset out the main points要点だけ。詳細は不要。
Compareidentify/comment on similarities and/or differences比較の各文に、両方の項目を入れる(「A は…、一方 B は…」)。
Suggestapply knowledge and understanding to situations where there are a range of valid responsescontext(シナリオ)に結びつけた妥当な案。
Calculate / Show (that)work out from given facts... / provide structured evidence that leads to a given resultworking を必ず書く(部分点)。単位の指定に従う。
Evaluate / Discuss / Justify
(AO3 の問い)		Evaluate: judge the quality... / Discuss: write about issues in depth in a structured way / Justify: support a case with evidence/argument利点・欠点 + 判断(結論)を書く。一文の結論と理由で締める。
Examiner が指摘する command word の落とし穴: 「identify」に説明を書く(時間の無駄)/「explain」に describe(点が取れない)/「purpose」「characteristics」「advantages」は違う答えを求める。 0478 ER Mar 2025 P12, Mar 2026 P12 / 9618 ER Jun 2025 P31–33

🧩 2. 問題タイプ別の解答フレーム

explain(2〜3点)

主張 → because → 結果。1点の主張に、理由か展開を必ず付ける。同じ内容の言い換えで2点は取れない。9618 ER Jun 2025 P11–13

context 問題

問題文の名詞(sensors の種類、tractor、検索エンジン)を答えの中の各文に入れる。「generic な説明 + 1文の context」は不可。0478 ER Mar 2025 P12, Jun 2026 P11–13

比較

各文に両方の項目。DRAM と SRAM のように、片方しか書かない答えは点がもらえない。9618 ER Nov 2025 P11 Q6(c)

3択から選ぶ・根拠を述べる

選んだ理由だけでなく、他の2つを除外する理由も書く(IPv4/IPv6/無効の判定など)。9618 ER Nov 2025 P11 Q7(b)

計算・変換

working を書く(部分点)。2進の加減算は2進のまま(10進に直すと点がない)。桁数の指定には先頭の 0 を書く。9618 ER Nov 2025 P11 Q1 / 0478 ER Jun 2026 P11

trace table

全ての変数を列に。実行順に1行ずつ。ループの各反復を省略しない。0478 では trace table が弱いと指摘。0478 ER Jun 2024 P21

図(flowchart・linked list・ER・ネットワーク)

矢印には矢じり、全ての経路を終端(STOP/null)へ。図には注釈(矢印が何を表すか)を付ける。0478 ER Mar 2026 P12 / Jun 2026 P21–23 / 9618 ER Jun 2025 P31 Q4(a)

K-map

元の式の項の数 = 1の個数。ループは1だけ、個数は2の累乗(2・4・8)。グループにならない1も最終式に必要。9618 ER Nov 2025 P31 Q6

✅ 3. CIE pseudocode 構文チェックリスト

答案を出す前に、生徒が自分で確認する。0478 はシラバス 4章で定義された形式、9618 は Cambridge の pseudocode guide に従う。失点例は Examiner Report から。

項目正しい形よくある誤り
代入Counter ← 0= を使う、結果を変数に代入しない(UCASE・SUBSTRING)
宣言DECLARE Counter : INTEGER
DECLARE Names : ARRAY[1:30] OF STRING		データ型の誤り(FLOAT ではなく REAL)、配列の範囲(要素50個なら 1:50)
比較<>(≠)、>=!=、=>
IFIF … THEN … ELSE … ENDIFENDIF の欠落
ループFOR i ← 1 TO 10 … NEXT i
WHILE … DO … ENDWHILE
REPEAT … UNTIL …		NEXT・ENDWHILE・UNTIL の欠落。FOR は回数が決まっている場合に使う
手続き・関数PROCEDURE … ENDPROCEDURE
FUNCTION … RETURNS INTEGER … ENDFUNCTION		END の欠落。関数で RETURN せず OUTPUT する
ファイルOPENFILE "A.txt" FOR READ
READFILE "A.txt", LineOfText
CLOSEFILE "A.txt"		ファイル名の引用符がない、CLOSE と書く、CLOSEFILE・EOF() にファイル名がない、mode の誤り。
9618 では mode に APPEND・RANDOM もある(pseudocode guide で確認)
識別子意味のある名前予約語(String、LENGTH、MONTH、TODAY)を使う

使い方: 印刷して机に貼る。答案を出す前に「END 文・file・予約語・型」の4項目を声に出して確認する習慣を最初の週から作る。

📖 4. Mark scheme の読み方を教える

  • 1点 = 1つの独立したポイント。同じ意味で言い換えた2文は1点(9618 ER Jun 2025 P11–13)。
  • 除外された答えに注意。「他の2つ」と書いてあれば、例示されたものは点にならない。
  • mark scheme の "AO"・アクセプト表現を毎回見て、自分の答えがどの表現にあたるかを確認する。
  • working の部分点(follow-through や benefit-of-doubt)があることを確認する(9618 ECR で言及)。
  • pseudocode は、ロジックと構文の両方に点があることを示す(構文ミスで点を失う)。
