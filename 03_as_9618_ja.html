📚 3. Paper 1:Examiner Report が示す失点と打ち手

出典は 9618 ER Nov 2025 P11(特記以外)。年度が違う場合は併記。

Sectionよくある失点打ち手
1 情報表現 ・2進 → 10進 → 16進と遠回りして計算ミス(2進 → 16進は直接変換できる)
・BCD を 8ビット2進と取り違える(0110 1100)
・2の補数で負の符号を忘れる(補数法で 68 を求めた後に「−」を付けない)
・2進の加減算を10進に直して計算すると点がもらえない
・オーバーフローの説明で「容量が足りない」とだけ書く(ビット数への言及が必要)		 ・2進のまま計算する練習を毎回(10進変換は検算にだけ使う)
・オーバーフローは「結果が○ビットを超え、収まらない」と書かせる
8 データベース ・多対多を結合テーブルで2つの一対多に分ける ER 図で、関係の向きが逆
・正規形の説明で「1NF・2NF である」とだけ書く(意味の説明が必要)
・SQL:DELETE FROM の誤り、FROM に不要な2つ目のテーブル、「完了」の条件の漏れ
・database・table・attribute の用語を誤用
・参照整合性:主キーと外部キーの依存関係を逆に説明、「この DB にどう当てはまるか」に答えない		 ・ER 図は認められた記法で描く練習
・参照整合性は「このテーブルのこの列は、あのテーブルのこの列に存在する値のみ」と具体的に書かせる
3 ハードウェア(論理) ・XOR ゲートの記号、NOT・NAND の丸が不明瞭
・真理値表の読み取りが弱い		 ・ゲート記号を毎回描く。真理値表から式を作る練習
4 プロセッサ(アセンブリ) ・binary shift の問いに XOR 命令を書く
・XOR &12(アドレス)と XOR #12(即値)を取り違える
・OR 100(アドレスの値)と OR #100 を取り違える		 ・アドレス指定(直接・即値)を、アキュムレータの値を毎回書き出して追う
5 システムソフトウェア ・メモリ管理・ハードウェア管理などの指定された2つのタスクではなく、他のタスクを列挙
・OS の役割と、アンチウイルス・ファイアウォールの役割を混同
・デバイスドライバーを曖昧に述べる
・library routine の欠点を述べても、2点目の「展開」が書けない		 ・「タスク名 → 何をするか → 何の役に立つか」の3点セットで書く
4 レジスタ ・data・address・instruction の用語を誤用
・レジスタ名を繰り返すだけ(例:「CIR は現在の命令を保持する」だけでは点にならない。decode・execute の記述が必要)
・2つを比較する問題で、片方の記述しか書かない(DRAM と SRAM)
・マルチコアの欠点(過熱、コア間通信による遅延)は書けるが、説明が不足しがち		 ・比較問題は「A は…、一方 B は…」の形を型にする
2 通信 ・static IP「変わらない」、public IP「公開されている」のように不十分
・不正な IP アドレスの根拠が曖昧(IPv4 でも IPv6 でもない理由を両方書く必要がある)		 ・3択から選ぶ問題は、他の2つを除外する理由を書く

出典:9618 ER Nov 2025 P11 Q1–Q7。Jun 2025 P11–13 の Key messages も同様の指摘(除外された答え、同一内容の言い換えは1点)。

💻 4. Paper 2:プログラミング・問題解決

AS の50%、AO3 が60%。 練習量が点数に直結する。CIE pseudocode の習熟が最優先。

Examiner が指摘する失点(Jun 2025 P21–23)

  • procedure/function の END がない、IF の ENDIF、WHILE の ENDWHILE、ループの終端がない
  • RAND・INT・LEFT・MID など、insert にある関数の使い方の誤り
  • 2D array の添字の書き方の誤り
  • file handling:OPENFILE の mode、CLOSEFILE・EOF() にファイル名がない
  • 予約語を変数名にする(String、LENGTH、MONTH、TODAY)
  • 関数が値を RETURN すべきなのに OUTPUT する
  • 変数の宣言・初期化・データ型がない
  • 「State a value」に変数名を書く、テストデータの条件を読まない
9618 ER Jun 2025 P21 / P22 / P23

設計の習慣(Examiner の提言)

  • 書く前に設計:count-controlled か conditional か、IF の連続か CASE か、引数は何か、データ型は何か
  • identifier table で変数を文書化する(変数の用途を記録)。コメントや配列ではない。9618 ECR P2 (2024) Q1(c)
  • 要件を「コーディングできる手順」に書き下す練習(Q4(a) は改善したと評価)
  • pseudocode は手で書き、構文チェックリストで自己採点
週1コマのプログラミング(80分)の型: 10分 前回の振り返り(構文クイズ)→ 15分 新しい構造の例 → 40分 課題(紙で pseudocode → PC で確認)→ 15分 trace table とレビュー。 詳細は 05・07。
