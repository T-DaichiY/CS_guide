IGCSE Computer Science 0478(G9–G10)

2年間のペーシング、Topic 別の指導の核と頻出失点、Paper 2 の15点問題の攻略。

🧭 1. コースの全体像

Paper 1(Topics 1–6)と Paper 2(Topics 7–10)が各50%。両方とも 1h45・75点・電卓不可(0478 シラバス 2026–2028)。

学年の割り当て(教材フォルダの構成から推定): G9 = Topics 1–6(Paper 1 の範囲)、G10 = Topics 7–10(Paper 2 の範囲)+ 総復習。 違う場合は下のペーシング表を差し替える。
注意: Paper 1 の範囲は G9 で終わるため、試験の約1年前に学んだ内容を覚えている必要がある。G10 の間も G9 の内容を定期的に引き出す(retrieval)仕組みが必須。
時間G9G10
週あたり80分×2 + 40分(200分)同左
年間(約32週)約107時間約107時間
Cambridge 想定(2年間で)約130時間 → 2年で約213時間あり、約83時間の余裕
この余裕をどう使うか: 新規内容の説明を短くし、余った約80時間を (1) 過去問演習(command word・context の訓練)(2) G10 の P2 プログラミング演習(3) G9 内容の定期復習 に使う。

🗓 2. 2年間のペーシング(提案)

1年32週・週3コマ(80分×2 + 40分)。週の型は 05 授業設計 を参照。

期間内容週数メモ
G9 前半Topic 1 Data representation約7週2進・16進・シフト・2の補数・容量計算。計算は必ず working を書く習慣を最初に作る
G9 前半Topic 2 Data transmission、Topic 3 Hardware約8週FDE サイクルのレジスタは図で理解させ、説明は用語で書かせる
G9 後半Topic 4 Software、Topic 5 Internet、Topic 6 Automated & emerging technologies約10週context 付きの記述問題(self-driving tractor、search engine など)を毎週1問
G9 後半Topic 7 の導入(pseudocode 基礎)約7週(並行)週1回(40分)は pseudocode を紙で書く。CIE 形式の構文を最初から固定する
G10 前半Topic 7 Algorithm design、Topic 8 Programming約16週trace table、flowchart、配列、file handling、library routines。最も時間をかける
G10 前半Topic 9 Databases、Topic 10 Boolean logic約8週SQL と論理回路は「満点を取れる」領域。ミスをゼロにする
G10 後半総復習・過去問(P1/P2)・15点シナリオ約8週弱点分類(00ページの4原因)ごとに補習

合計:G9 約32週、G10 約32週。各週数は目安で、実際の学校暦に合わせて調整する。

📚 3. トピック別:教える核・頻出失点・打ち手

失点はすべて Examiner Report の記述。直近(2026年6月)を中心に引用。

Topic教える核頻出失点(Examiner Report)打ち手
1 Data representation
P1		2進・10進・16進の変換、2進加算、論理シフト、2の補数、テキスト・音・画像、容量計算、圧縮 ・データ量の換算で 1024 でなく 1000 で割る(3 KiB を 3.072 とする)
・8ビット/12ビットにするための先頭の 0 を書かない
・オーバーフローの計算で繰り上がりの working を書かない
・「16進数は少ないメモリで保存できる」「2進数で表せる最小の整数は1」という誤概念
0478 ER Jun 2026 P11–13 / Mar 2024 P12 / Mar 2025 P12		 ・単位は KiB/MiB…の「ladder」を教室に掲示し、毎回 ÷1024 を声に出して確認
・桁数指定の問題は「桁数を先に書く」ルール
・誤概念を「正しい?間違い?」クイズで単元の最初に出す
2 Data transmission
P1		パケット、シリアル/パラレル、エラー検出、暗号化 ・シリアル通信を「1本の線で1ビットずつ送る」と書けず、1ビットずつ送る点に触れない
・「長距離に強い」と書くだけで、問題の context に結びつけない
0478 ER Jun 2026 P11–13 (パケットの理解は良好:Mar 2025 P12)		 ・「特徴 + context」の2文セットで書かせる(例:〜なので、このシナリオでは…)
3 Hardware
P1		CPU とレジスタ、FDE サイクル、入出力装置、センサー、記憶装置 ・FDE の最初に使うレジスタを MDR とする(メモリ上の「アドレス」と「命令」の混同)
・CIR は decode 段階だけで使われることを理解していない
・オンスクリーンキーボード(ソフトウェア)を入力装置とする/ヘッドホンを内蔵装置とする
・「センサー」の名前が曖昧(sound sensor/motion sensor など、より技術的な参照が必要)
・問題文で既に例示されたものを答えに書く
・「性能にどう影響するか」でクロック速度の増減の方向を書かない
0478 ER Jun 2026 P11 / P12 / Mar 2024 P12		 ・FDE は「各ステップで何がどこへ送られるか」を図とアニメで確認 → 文章で書かせる
・センサーは「何を測る/何が起きたら何をする」の3点で書かせる
・問題文の例示と重複しないことを、解答前の確認項目にする
4 Software
P1		OS の機能、translator(compiler/interpreter/assembler)、IDE ・欠けたメモリ(missing memory)を特定しながら、2つ目の機能を「ユーザー管理」とする
・「コードは2進数に変換される」だけで、high-level language に触れない
・問題文で既に与えられた translator を答えにする
・IDE の機能の説明に必要な技術的要素が欠ける(例:auto-correct は「コードのエラーを直す」と書く)
0478 ER Jun 2026 P11–13		 ・translator は「入力 → 出力 → 実行のタイミング」の3点表で比較
・IDE の機能は「機能名 + それが何をするか + 何の役に立つか」
5 Internet
P1		URL と IP、web browser/server、cookie、デジタル証明書、セキュリティ ・web server と web browser を取り違える
・デジタル証明書:証明書の要求と送信は書けるが、証明書の認証とデータの暗号化が抜ける
0478 ER Jun 2026 P11–13 (URL → IP の理解は良好:Mar 2026 P12)		 ・TLS/証明書は「手順の図」を描かせ、各矢印に説明を書かせる(図には注釈が必要)
6 Automated & emerging technologies
P1		自動化、ロボット、AI、センサー、自動運転 ・「検索エンジンで機械学習がどう使われるか」に、一般的な ML の説明だけを書く
0478 ER Mar 2025 P12
(self-driving tractor のセンサーの用途など、context 付きの答えは改善:Mar 2024 P12)		 ・毎週「新しいシナリオ + 同じ知識」で書かせる(例:tractor → 倉庫ロボット → 病院)
7 Algorithm design
P2		開発ライフサイクル、flowchart、trace table、アルゴリズムのエラー発見・訂正 ・flowchart の矢印に矢じりがない/全ての経路が STOP で終わらない/条件とループを使わず巨大になる
・flowchart の問いにアルゴリズムの観点で答える
・正しい flowchart 記号を使わない、trace table が弱い
0478 ER Jun 2026 P21–23 / Jun 2024 P21 (アルゴリズムのエラー発見・訂正は良好:Jun 2026 P22–23)		 ・trace table は毎週1問。列の見出しを自分で書く練習
・flowchart 記号表を暗記ではなく「描いて使う」
8 Programming
P2		変数・配列・ループ・selection・library routines・file handling・15点シナリオ ・REAL を FLOAT と書く/「≠」を != と書く(正しくは <>)/ >= を => と書く
・DIV と MOD を library routine とする
・配列の最後のインデックスを 49 や 51 とする(要素は50個)

・FOR ループが「繰り返し回数が決まっている」ことを書かない
・関数の RETURN が抜ける
・short-answer で Python を書く(許されるのは15点問題のみ)

⭐ 4. Paper 2 の15点シナリオ問題を攻略する

Paper 2 の最終問題。未見のシナリオ、15点、目安30分、pseudocode または Python / Visual Basic / Java で解答可(0478 シラバス)。AO2 を最も多く含み、最も点差がつく。

解答の手順(Examiner Report に基づく)

  • 最後まで読んでから書く。0478 ER Mar 2024 / Mar 2025 / Jun 2025 / Jun 2026 P22
  • 変数・配列が「宣言不要」と書いてあれば宣言しない。書いてあれば宣言する。
  • シナリオで指定された変数・配列を、指定どおりに使う。初期化が必要なら初期化する。
  • すぐに本体を書く。与えられたタスクに集中する。
  • コメントを書く。各部分が何をしているかを示す。0478 ER Jun 2026 P22
  • 使える言語は pseudocode / Python / Visual Basic / Java のみ。

訓練の進め方

  • G10 前半:短い問題で部品(入力、ループ、配列、条件、出力)を別々に練習。
  • G10 中盤:過去問の15点問題を毎月1題、制限30分で。
  • 採点:mark scheme で自己採点 → 「読み落とし」「構文」「ロジック」に分類。
  • 復習:同じ種類の誤りが出たら、構文チェックリストにその項目を追加。
落とし穴: 「ロジックは合っているが、指定された変数名を使っていない」「出力の条件を見落とす」ことで点を落とす。 Examiner はシナリオに正確に従うことを毎回強調している。

🧠 5. G9 内容を G10 まで保持させる

Paper 1(Topics 1–6)は G9 で学び終え、試験は約1年後。忘却を前提にした設計が必要。

  • 毎週の40分の授業の前半10分:G9 トピックからランダムに2問の復習(前週・先月・昨年のトピックを混ぜる)。
  • 学期末:G9 全 Topic から30点の mini test。結果をトピック別に記録する。
  • G10 後半:Paper 1 過去問を月1回実施し、command word・context の失点を分類する。
  • 0478 の過去問は My Drive/Past papers/Past papers/0478 Computer Science - IGCSE/ に年度別に保管されている。
