⭐ 3. 層別の介入

A* 圏(得点率の上位層)

  • AO3 の問い(evaluate・discuss・justify)の結論の書き方
  • P4:evidence document の完璧な体裁、テストの網羅性
  • 0478:15点問題で、シナリオの全項目を満たす
  • 残る失点は S(構文)・X(重複)・W(working)が多い → チェックリストで消す

ボーダー層(A/B を狙う)

  • 最も大きい失点列(C か S)を1つだけ決めて集中的に直す
  • command word 別の書き方フレーム(06)を毎週
  • プログラミング:紙の pseudocode を週2回

下位層(pass 圏)

  • K(未習)を特定し、事前学習の確認を個別に
  • 確実に取れる領域を先に:2進変換、論理回路、SQL の基本
  • 短い pseudocode 課題を毎週(段階1–2)
grade threshold について: A*・A の境界点は、Cambridge がシリーズごとに公開する。層の分け方(上位・ボーダー・下位)は、直近 mock の得点率と、公開された grade threshold を見ながら決める。

⚠️ 4. この科目で陥りやすい失敗

  • 説明で時間を使い切る:AS・A2 は時間が足りない。初回の説明を事前学習に移す(05)。
  • プログラミングを理論の後に回す:練習量が足りなくなる。最初の週から毎週1コマ(03・04)。
  • 過去問を直前にまとめて解く:弱点が分かっても直す時間がない。月1回の C 回(05)。
  • PC で書き、紙で書かない:0478・9618 P2 は紙の pseudocode。構文を意識しない癖がつく。
  • mark scheme を答え合わせにだけ使う:表現の取り方・点の分け方を学ぶ道具にする(06)。
  • G9 の内容を G10 で復習しない:Paper 1 の範囲は約1年前に終わっている(02)。
  • P4 の evidence document を直前に教える:毎回の課題で作法を固定する(04)。
